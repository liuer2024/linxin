# 邻信 · Linxin

**发现身边的设备，直接聊天、传文件。**

邻信是一款开发中的轻量桌面通信工具，面向 macOS 与 Windows。以局域网自动发现为起点，结合即时聊天与文件传输，并通过已安装的 Tailscale 客户端探索不同网络之间的连接。

使用 **Go + MyGo** 构建原生界面，无 React、WebView 或浏览器运行时。

> 当前为开发预览版：已完成 macOS 本机多实例联调；Windows 真机与真实 Tailscale 跨网验证仍待完成。暂未提供正式安装包。

## 能做什么

| 功能 | 当前实现 |
| --- | --- |
| 附近设备 | UDP 组播自动发现，设备上线刷新；支持手动地址连接 |
| 多人单聊 | 独立会话、消息摘要、草稿、滚动位置与未读计数 |
| 消息状态 | 送达确认、可见消息已读回执、失败消息重试 |
| 文件传输 | 邀请、接收或拒绝、流式传输、进度、取消接收、SHA-256 校验 |
| 设备身份 | 持久化设备证书、指纹核对与信任记录、TLS 1.3 连接 |
| Tailscale | 读取本机客户端状态、发现远端设备；设置中可启用或关闭 |

发现设备后可以直接发起聊天或文件邀请。单纯发现不会自动创建聊天会话，文件也不会默认自动接收。

## 界面与交互

- **发现**：类似 AirDrop 的设备视图，区分附近设备与 Tailscale 设备，点击设备聊天或发送文件。
- **消息**：导航栏、最近会话、聊天内容组成的桌面布局；每个人拥有独立的未读状态和草稿。在输入框粘贴剪贴板里的图片或文件即直接发送，「截图」按钮调用系统截图后发送；图片在会话中直接显示预览。
- **传输**：汇总各个会话的文件任务，查看进度与结果，跳转到对应会话或打开所在文件夹。
- **设置**：原生弹窗管理 Tailscale 功能，以及是否随邻信启动已安装的 Tailscale 客户端。

## 快速开始

开发环境需要 **Go 1.27.3 或更高版本**，桌面模块使用 **MyGo v0.8.3**。目前优先在 macOS 上开发和验证。

```sh
git clone https://github.com/liuer2024/linxin.git
cd linxin/desktop
go mod download
go run .
```

同一局域网的两台设备启动邻信后，进入「发现」选择对方。首次建立信任时，通过可信渠道核对完整设备指纹。

默认使用 TCP **47832** 进行 TLS 通信，UDP **47831** 进行发现，组播地址为 `239.255.87.15`。防火墙需要允许相应通信；访客网络、路由器设备隔离或组播限制可能影响发现，此时可在发现页手动填写对方的 `IP:端口` 和指纹。

### 一台电脑体验两端

在 `desktop` 目录分别打开两个终端，使用独立数据目录和端口：

```sh
# 终端 A
go run . -name 模拟Mac -data ../.cache/device-a -listen 127.0.0.1:47901
```

```sh
# 终端 B
go run . -name 模拟另一台电脑 -data ../.cache/device-b -listen 127.0.0.1:47902
```

两个实例可自动发现彼此，用于体验聊天、已读未读和文件传输。此方式不能替代真实的跨设备、跨操作系统测试。

### 通过 Tailscale 跨网络连接

1. 两端分别安装并登录 Tailscale，确保所在 tailnet 与访问策略允许双方互通。
2. 在邻信设置中启用 Tailscale，在「发现 → Tailscale」重新探测设备。
3. 对方也需运行邻信，并允许访问通信端口；首次连接仍需核对邻信设备指纹。

邻信使用外部 Tailscale 客户端，不内嵌 VPN，也不会替你执行 `tailscale up/down`。关闭邻信中的入口不会退出系统 Tailscale。当前已验证模拟 CLI 和本机协议流程，**真实跨网连通性、直连或中继下的表现尚待验证**。详见 [Tailscale 使用说明](docs/TAILSCALE.md)。

## 技术与性能取舍

- **原生界面**：Go + MyGo，减少额外浏览器运行时依赖。
- **发现与传输分离**：UDP 组播发现设备，TLS/HTTPS 承载聊天和文件；发现不会自动建立会话。
- **流式文件传输**：避免将整个文件载入内存。发送前先计算哈希，传输后校验完整性，因此准备阶段会额外读取一次文件。
- **不覆盖已有文件**：接收时使用同目录临时文件与硬链接发布，目标文件名必须未被占用；接收磁盘需要支持硬链接，例如 APFS、NTFS。
- **外部网络接入**：Tailscale 负责网络互通，邻信继续使用自身设备身份与传输协议。

体积和速度需按最终平台、构建方式、磁盘及网络环境实测；目前没有正式发行包或跨设备性能承诺。

## 当前边界与后续计划

**聊天记录、草稿、文件邀请和任务目前只保存在内存中，退出应用后不保留。** 设备身份、信任记录与设置会保存。

后续重点：

- [ ] 聊天历史持久化与数据管理
- [ ] Windows 真机、真实 Tailscale 跨网验证
- [ ] 连接恢复、文件夹传输与断点续传
- [ ] 系统通知与托盘交互
- [ ] 阅后即焚的协议、计时与清理机制

当前不支持群聊、离线投递或账号同步。阅后即焚尚未实现；未来的消息清理也无法阻止对方截图或自行保存内容。

## 开发与验证

在仓库根目录执行（测试需要允许本机 TCP/UDP 通信）：

```sh
go test -race ./internal/...
go vet ./internal/...
```

文件传输基准测试：

```sh
go test ./internal/lan -run '^$' -bench BenchmarkTransfer32MiB -benchtime=3x
```

项目采用双模块结构：根模块包含协议、发现、消息与传输逻辑，`desktop/` 包含 MyGo 桌面应用。当前阶段以功能迭代和本机验证为主，尚未配置三平台自动打包或正式发布流程。
