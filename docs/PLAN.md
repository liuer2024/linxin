# 局域网会话工具实现方案

纯 Go，MyGo 原生 UI；Mac / Windows。会话以持久化设备公钥标识，不以 IP 或设备名称标识。

## 第一阶段

1. 通信核心：设备身份、TLS 服务、首次发现未验证提示、手动连接兜底。
2. 消息：唯一 ID、送达确认、去重、未读计数、明确触发的已读回执。
3. 文件：邀请后确认、临时文件、流式传输、大小限制、SHA-256 校验、重名保护。
4. MyGo：左侧设备/会话，右侧消息与输入；文件选择、接收操作、状态反馈。
5. 自动发现：mDNS；设备离线保留会话；网络变化重新发现。

## 协议与安全

所有网络操作有超时；元数据限制大小；消息正文限制长度。首次连接应展示证书指纹供双方核对，可信后固定证书。未经验证的设备不得标成可信。文件路径仅使用接收端选择目录与安全文件名。默认不自动接收文件。

聊天状态：等待发送 → 已送达 → 已读；失败可重试，相同 ID 不重复入库。
文件状态独立：邀请 → 接受/拒绝 → 传输 → 校验 → 完成/失败。
已读只在应用聚焦、会话打开且消息可见时推进；收到网络数据不视为已读。

## 性能预算与验收

发布包争取单架构 20 MB 内，空闲内存 100 MB 内，均需实测。文件不进入 UI、不做 Base64，固定缓冲；进度限频。大文件与消息连接独立。
测试两实例消息、去重、已读、文件拒绝/接收、断线、重名及恶意路径。真实 Mac/Windows 验证权限、防火墙、中文输入、休眠恢复和吞吐；基准包括大文件及大量小文件。

## 后续

持久化会话、可靠重试、断点续传、托盘；随后阅后即焚（独立内容密钥、到期删除、通知与日志不保留明文），最后公网协调/穿透/中继。不承诺防截图或接收者复制。

## 实施进展（2026-11-08）

已实现持久身份与人工信任记录、TLS 服务、双向 hello、消息收发/送达/可见已读、重试、文件邀请/拒绝/拉取/校验/进度/取消，以及 MyGo 原生会话 UI。
自动发现先采用标准库 UDP 组播以控制依赖，替代最初设想的 mDNS。后续根据真实网络测试决定是否增加 mDNS。

开发版消息暂存内存。下一阶段优先：双实例 GUI 验收、历史记录加密存储、托盘与通知、文件夹和断点续传、网络切换恢复，再实现阅后即焚。

## Tailscale 接入

采用外部已安装的 Tailscale CLI 获取本机状态和 tailnet 设备，不引入 VPN SDK。新增原生设备来源切换、刷新、在线/离线和登录状态、端口选择及连接入口。连接前探测 `/v1/identity` 的公开身份，再用证书指纹建立 hello；成功后按 Tailscale 稳定设备 ID 保存应用指纹绑定。CLI 候选仅接受 Tailscale IPv4/IPv6 地址，不使用组播跨网发现。

不启用 VPN 或 Funnel、不自动登录或变更 ACL。真实跨网络联调需要已安装并登录的两端 Tailscale，当前仅完成模拟状态与本机双服务协议验证。详见 TAILSCALE.md。

## 界面与发现重构（2026-11-08）

已分离消息、发现和传输页面，设置保持弹窗。消息采用窄导航栏、最近会话列表、当前聊天区；加入摘要、时间、独立未读、按活动排序、搜索、独立草稿和列表滚动状态。聊天使用左右气泡，网络信息与指纹收纳到按需展开的详情。

发现页使用居中设备图标与名称，提供聊天、文件选择和文件拖入设备图标的操作。局域网与 Tailscale 分范围展示。文件传输汇总跨会话任务并可返回对应会话。

发现服务改为逐网卡加入组播组、显式选择发送网卡、受限并发身份探测、主动查询应答、心跳重探测和网卡变化重建。公告只触发公开身份探测，不创建会话；连接或收到消息才产生会话数据。同机模拟实例支持回环地址公告，仅在公告源属于本机地址时使用。
